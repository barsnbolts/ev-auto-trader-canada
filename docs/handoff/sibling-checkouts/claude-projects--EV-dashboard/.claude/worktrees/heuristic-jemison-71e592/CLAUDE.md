# CLAUDE.md — EV Dashboard project

**For any Claude session starting fresh on this codebase.** Read this first. Then SESSION_SUMMARY.md for current stage. Everything else links from there.

## What this is

A personal-use Mac app for Ian McAdam (Ontario, first-time EV buyer) to compare every EV / PHEV / EREV for sale in Canada. New and used. Not a shipped product — no signing, no distribution, no auto-update. Ian runs it on his MacBook Pro; he and his mom use it to research his next vehicle.

## Non-negotiable principles

1. **Scientific rigor.** Every number displayed is cited and tagged with confidence (High / Medium / Low). Never fabricate precision — mark Low and move on.
2. **Traceability.** Every claim has a `source` field pointing to the URL it came from, with the date accessed. Stored inline in seed.json.
3. **Personal use only.** If a proposal smells like "for shipping," kill it. No code signing, notarization, or distribution infra.
4. **Scope discipline.** Long-range trims only: longest-range single-motor variant + longest-range AWD variant. Skip base trims, skip performance trims. Distinct entries per generation.

## Tech stack choices — and why

| Layer | Choice | Why |
|---|---|---|
| Desktop shell | Tauri 2 | Apple Silicon native, tiny bundle, far better than Electron on Mac |
| UI | React + TS + Vite | AI-coding-friendly, fast HMR |
| Styling | Tailwind + custom tokens | Clean dark-showroom aesthetic; no shadcn because not needed at this size |
| State | Zustand | Minimal boilerplate for filter + compare state |
| Local DB | SQLite (Phase 2+) | File-based, zero-config, perfect for ~60-row dataset |
| Scrapers | Python + Playwright (Phase 2) | Best scraping ecosystem; mostly deferred in favor of on-demand Exa verification |
| Data source | Hand-curated seed.json w/ citations (Phase 1) → Exa verification (Phase 2b) | Personal use = one user = no scrape infra needed |
| Physics model | Pure TS, parameterized per vehicle | Published curves (Geotab, Recurrent, Fastned, Bjorn Nyland, P3) |

## Data model

`seed.json` → `Vehicle[]`. Every measured field is a `CitedValue<T>`:

```ts
{
  value: T | null,
  source?: { url, name, accessed: "YYYY-MM-DD" },
  confidence: "High" | "Medium" | "Low",
  notes?: string
}
```

See `src/types.ts` for the full shape.

**Generations matter.** IONIQ 5 pre-2025 and IONIQ 5 2025+ are *different vehicles* in this data. Never collapse them — battery size, thermal system, and charging curve all change.

## Token-saver wrapper — `scripts/quiet.py`

Inspired by [rtk-ai/rtk](https://github.com/rtk-ai/rtk). Project-scoped, single Python file, no external install. Wraps verbose dev commands so their output gets to me already filtered to the salient lines.

**Always wrap these via quiet.py** (typical savings: 70–95% of output tokens):

```bash
python3 scripts/quiet.py npx tsc --noEmit               # 200 → 3 lines
python3 scripts/quiet.py npm test -- --run              # 300 → 8 lines
python3 scripts/quiet.py cargo test                     # 180 → 5 lines
python3 scripts/quiet.py git status                     # 40  → 6 lines
python3 scripts/quiet.py git diff                       # capped at 200 lines
python3 scripts/quiet.py git log --oneline -20          # capped at top 12
```

What gets through always: errors, FAIL blocks, WARN lines, the underlying tool's summary line, exit code. What gets dropped: per-test-pass spam, tsc compile-progress, npm deprecation noise.

A trailing line `[quiet.py: <kind> | ~before→after tokens, -X%]` makes the savings auditable.

`scripts/milestone.py` already wraps tsc / vitest / cargo through `_quiet()` so every milestone benefits with no extra effort. For ad-hoc bash from chat, prefer the `quiet.py` wrapper unless I genuinely need the raw output (e.g. debugging the wrapper itself).

## Reasoning-level awareness — task-boundary check

The active model + reasoning effort are auto-detectable. At the **start of every new task** (any item from `.queue_top3.md`, any TodoWrite item flipped to `in_progress`, any new "section" of work):

```bash
python3 scripts/check_level.py --task <task-tag>
```

Exit 0 → fits, proceed. Exit 1 → mismatch. On mismatch the standing policy is **switch to a smaller queued task automatically** (per Ian 2026-04-24): re-rank with `python3 scripts/queue.py --respect-level` and pick the top compatible item. If nothing fits, stop and report.

**To know the current level any time:** `python3 scripts/detect_level.py`. Reads the Claude Desktop session JSON (`~/Library/Application Support/Claude/claude-code-sessions/.../*.json`), prints model + effort + last-activity. No user action needed.

**Task tags** are catalogued in `docs/task_complexity_map.md` (data: `scripts/task_complexity.py`). Add a new tag when a task type doesn't fit any existing one.

### Bidirectional model recommender (H10)

`scripts/recommend_model.py` runs every milestone (step 10) and on demand. It detects the current level, ranks the queue, and decides:

- **silent-swap** (default) — pick the top compatible item, do that. No interruption to Ian.
- **nudge-down** — when the next 3 compatible tasks all fit a strictly cheaper level (≥3× cost saving). Print one line: "switch to <level>, ~Nx cheaper for these 3 items".
- **nudge-up** — when a top-3 priority queue item is parked one model-tier above current. Print "switch to <target> to unblock <item>".
- **stop-no-work** — nothing fits or queue is empty. Stop and report.

Always-on logs:
- `logs/level_recs.md` — append-only timestamped recommendation history (one line per milestone).
- `logs/deferred_tasks.md` — running list of queue items parked above current level, grouped by required level. Auto-rewritten each run. After a level switch, this file shows what unlocks.

Cost weights live in `scripts/cost_model.py` (Haiku=1, Sonnet=3, Opus=5; effort low=0.5 → max=5; per-task-tag rough token bucket). Adjust there.

On-demand: `python3 scripts/recommend_model.py` (current detected level), `--simulate sonnet:medium` (what-if), `--json` (machine-readable).

### Empirical learning loop (H11)

The constants in `cost_model.py` (TASK_TOKENS) and `task_complexity.py` (TASKS minimums) self-calibrate from real milestones. Two halves:

**Passive** — every milestone records one observation row via `scripts/observation.py` into `logs/task_observations.jsonl` capturing model + effort + task tag + git lines changed + a self-estimate of tokens used. Pass `--cost-tokens N --confidence {low,medium,high} --task-tag <tag>` on the milestone command:

```bash
python3 scripts/milestone.py H11 "summary" --cost-tokens 30 --confidence medium --task-tag architectural-refactor
```

After every 5 new observations, `scripts/calibrate.py --maybe` runs automatically (milestone step 12) and applies updates per the asymmetric rules below.

**On-demand active** — `python3 scripts/stress_test.py --suite quick` prints a battery of canonical tasks with objective rubrics. Work through them, run `--record <id> --passed` or `--failed` after each, then `--finish` to fold into calibrate.

**Asymmetric aggression rules** (per Ian: conservative-down, eager-up):
- LOWER min for tag X: ≥3 *consecutive* successful observations at a strictly cheaper level. Single failure resets the counter.
- RAISE min for tag X: any single failure at the current min level immediately bumps it up one tier.
- UPDATE TASK_TOKENS for tag X: ≥5 observations AND median changes by ≥20% from current.

Every change goes into `logs/calibration_changes.md` (gitignored) with timestamp + before/after diff.

Files: `scripts/observation.py`, `scripts/calibrate.py`, `scripts/stress_test.py`, `scripts/test_calibrate.py`, `docs/stress_test_battery.md`.

**When to do the check:**
- Session start (after reading `.resume.md`).
- Every TodoWrite `in_progress` flip.
- Before invoking any spec-writing, architectural-refactor, or physics-model-change task.
- Whenever a tool call response feels "off" (latency or quality drift suggests a level change happened mid-session).

The cost is one short subprocess call. ~50 ms. Effectively free.

## Research-first rule + parallel-dispatch default

Before implementing anything expected to take >30 min, run a WebSearch / WebFetch sweep for existing libraries or tools. Write findings to `docs/research/<topic>.md` — name, URL, free/paid, one-line role, ROI note. Dead-ends still get logged so next session doesn't repeat the search.

**Parallel-dispatch is the default for ANY research touching ≥3 facts or ≥2 sources.** Serial WebSearch is forbidden for multi-fact tasks. Use:

```bash
python3 scripts/research.py "<topic>" --angles 4         # general topic → 4-angle parallel plan
python3 scripts/research_vehicle.py "Brand Model Year"   # full seed.json field sweep, 6 disjoint agents
```

Each script writes a parallel-execution plan to `docs/research/auto/`. Read it, then send ONE tool message with all the `Agent` calls in parallel. Total wall-clock = slowest agent. Full pattern + source matrix + tool inventory: [docs/research/playbook.md](docs/research/playbook.md).

Rationale: lost hours on hand-built solutions when proven libraries existed. Applied 2026-04-24: found OpenEV Data, MapLibre Metal, tauri tracing, Observable Plot, NHTSA vPIC, NRCan fuel data. Per Ian 2026-04-24: "deeper faster" — serial loops banned.
