## 1. Amortization libraries

**Decision: USE `@travishorn/financejs`**

- Top candidate: `@travishorn/financejs` v1.19.1, actively maintained (latest publish Apr 24 2026), 296 weekly downloads
- Install: `npm install @travishorn/financejs`
- Size: 93.1 KB unpacked, 37 files, 0 dependencies — lean
- TypeScript: Yes — strict type-checking, JSDoc, native ESM + CJS, named function exports (no class wrapper)
- Functions available: `pmt`, `pv`, `fv`, `ipmt`, `ppmt`, `cumipmt`, `cumprinc`, `rate`, `nper`, `irr`, `xirr`, `npv` — covers every standard loan/lease calc needed
- Excel-style conventions (pv negative for loans, type 0/1 for arrears/advance) — matches what a Canadian dealer finance sheet uses
- Last commit: Mar–Apr 2026 (actively developed; Tiers 1–3 complete, Tier 4 bond math in progress)
- GitHub: https://github.com/travishorn/financejs
- Reason to use: Zero-dependency, strict TS, 100% test coverage, actively maintained in 2026, covers loan payment + lease residual math with `pmt(rate/12, term, -principal)`. One import replaces ~30 lines of hand-rolled finance code.

Inline alternative if skipped:
```ts
// PMT — monthly payment for flat-rate loan
const pmt = (annualRate: number, months: number, principal: number) => {
  const r = annualRate / 12;
  if (r === 0) return principal / months;
  return (principal * r * Math.pow(1 + r, months)) / (Math.pow(1 + r, months) - 1);
};
```

## 4. AutoTrader / Kijiji deep-link templates

**Decision: VERIFIED — templates confirmed working 2026-05-02**

### AutoTrader Canada
Tested URL `https://www.autotrader.ca/cars/hyundai/ioniq+5/on/?rcp=20&rcs=0` → 200 + listings rendered (76 results confirmed in Ontario for Ioniq 5).

**Template:**
```
https://www.autotrader.ca/cars/{make}/{model}/{prov}/?rcp=20&rcs=0
```

Parameters:
- `{make}`: lowercase (e.g., `hyundai`, `kia`, `tesla`)
- `{model}`: lowercase, spaces as `+` (e.g., `ioniq+5`, `ev6`, `model+3`)
- `{prov}`: lowercase 2-letter province code (e.g., `on`, `bc`, `qc`)
- `rcp=20` = results count per page, `rcs=0` = start offset

Filtering: Add `?rcp=20&rcs=0&priceFrom=&priceTo=&yearFrom=&yearTo=` etc. as needed. `&YearMin=2020&YearMax=2026` for year filtering.

For used-only: `https://www.autotrader.ca/cars/{make}/{model}/{prov}/?rcp=20&rcs=0&sts=Used`

### Kijiji Canada
Tested via search results. Two confirmed patterns:

**Pattern 1 — keyword search (most reliable for specific models like "ioniq 5"):**
```
https://www.kijiji.ca/b-cars-trucks/{location}/{keyword}/{make-filter}?dc=true
```
Confirmed example (76 results):
`https://www.kijiji.ca/b-cars-trucks/ontario/ioniq-5/hyundai/k0c174l9004a54`

**Pattern 2 — make + model category (older Ioniq models):**
`https://www.kijiji.ca/b-cars-trucks/ontario/hyundai-ioniq/c174l9004a54a1000054`

**Recommended template for EV listings:**
```
https://www.kijiji.ca/b-cars-trucks/{province-slug}/{model-keyword}/{make-slug}/k0c174l9004a54
```
Where:
- `c174` = Cars & Trucks category
- `l9004` = Ontario location code; other provinces have different codes
- `a54` = Hyundai make attribute; other makes differ

For national search: replace `l9004` with `l0` (Canada-wide).
Example: `https://www.kijiji.ca/b-cars-trucks/canada/ioniq-5/hyundai/k0c174l0a54`

### Leasebusters
The Leasebusters search is form-based (POST, no URL parameters that encode make/model). The search URL is always `https://www.leasebusters.com/vehicle-search/Leasing` with no filterable query string. Deep-linking to a pre-filtered search is NOT possible. The probe doc's template approach will need to use the base URL + "open in browser" pattern, or link to their EV filter: `https://www.leasebusters.com/vehicle-search/Leasing` (user selects make manually). Note: site blocks non-CA/US IPs — works fine for Canadian end users.

## 5. Tauri 2 + Next.js

**Decision: CONFIRMED VIABLE — use `kvnxiao/tauri-nextjs-template` as reference**

- Reference repo (Tauri 2 + Next.js App Router + SSG): https://github.com/kvnxiao/tauri-nextjs-template
  - Stars: active, maintained (Next.js 16 / Tailwind 4 in latest update, forked by multiple users with Next.js 15)
  - Confirmed working: `pnpm tauri build` triggers Next.js SSG export then Tauri bundling
  - Forked variant with Next.js 15 + shadcn: https://github.com/Lightbridge-KS/taurinext-shadcn (Next.js 15.5.5, React 19, Tauri v2, Oct 2025)

**Required `next.config.js` settings:**
```js
const nextConfig = {
  output: 'export',      // REQUIRED — SSG only, no Node.js server
  distDir: '../dist',    // Tauri expects static files in a specific dir (or configure in tauri.conf.json)
  images: { unoptimized: true },  // next/image optimization requires server; disable for static
  trailingSlash: true,   // optional but recommended for file-based routing in static export
};
```

**Known incompatibilities with App Router + Tauri (static export mode):**
- No SSR (server-side rendering) — all data fetching must be client-side or build-time
- No API routes (`/app/api/` routes) — no Node.js server in Tauri
- No Server Actions that write to DB at request time — use client-side fetch to Rust Tauri commands instead
- No cookies-based auth via Next.js middleware — auth state must live in localStorage or Tauri secure storage
- No `next/headers` or `cookies()` in App Router Server Components
- `generateStaticParams` IS supported for dynamic routes; used for pre-rendering vehicle detail pages at build time
- Streaming / React Server Components with async data: build-time only

**Summary**: For ev-auto-trader-canada (read-mostly, JSON data, no user auth in Phase 1), these constraints are non-issues. The Tauri wrap is indeed straightforward when scoped to: static JSON data + client-side filters + Tauri shell for native window.

## 6. Vercel Next.js 15 deploy

**Decision: NO SPECIAL CONFIG NEEDED for standard Next.js 15 App Router web deploy**

**Framework detection**: Vercel auto-detects Next.js from `package.json` — no explicit `vercel.json` needed for standard deploys. If needed, add:
```json
{ "framework": "nextjs" }
```

**Production-branch override**: Dashboard only (no CLI flag). Path: Project Settings → Environments → Production Branch → enter custom branch name → Save. There is no `vercel --prod-branch=foo` CLI flag. Change is applied to all future deployments.

**Cookies + auth + preview URL issues (confirmed bugs 2025–2026):**
- Intermittent `cookies().get()` failures in Middleware reported May 2025 (Next.js issue #78831). Root cause: `cookies()` is async in Next.js 15 and must use `await cookies()` not `cookies()`. In Middleware specifically, use `request.cookies` (synchronous Edge API), not `cookies()` from `next/headers`.
- Cookies set in Server Actions are only available on the **next request**, not the current render — causes hydration mismatches if read immediately client-side.
- Streaming architecture in Next.js 15.5 prevents setting cookies directly from Server Components (headers already sent). Use Route Handlers or Middleware for cookie writes.
- Preview URL cookies: Vercel preview deployments have different origins than production; `httpOnly` cookies scoped to production domain won't be sent on preview URLs. Set `domain` carefully or use session tokens that don't rely on domain-scoped cookies for preview testing.

**Build timeout for ~100 JSON units + ~10 routes**: Not a concern. Vercel default timeout is 45 min; a static Next.js build with 100 vehicle pages takes ~30 seconds.

**vercel.json minimal config (if needed):**
```json
{
  "$schema": "https://openapi.vercel.sh/vercel.json",
  "framework": "nextjs"
}
```
