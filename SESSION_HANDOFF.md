# SESSION_HANDOFF.md

**Read this first if you're picking up work from any session — cloud, MacBook,
iOS Working Copy / Termius, fresh laptop, anything.**

The repo runs across multiple environments. To avoid divergent histories
and silently-clobbered work, every session begins and ends with the same
ritual.

## When you start a session

```bash
cd ~/ev-auto-trader-canada       # or wherever the clone lives
git checkout main
git pull --rebase origin main
```

`--rebase` keeps history linear — local-only commits replay cleanly on top
of whatever a previous remote session committed. Without it, parallel
sessions create merge bubbles that are hard to read in `git log --oneline`.

If the rebase reports conflicts, **stop and read them.** Most likely a
prior session committed a partial edit to the same file you're about to
touch. Resolve manually; do not auto-resolve to "ours."

## When you finish a meaningful chunk of work

```bash
git status           # confirm what's about to ship
git add <files>      # stage explicitly — never `git add -A` in this repo
git commit -m "<conventional commit>"
git push origin main
```

If `git push` is blocked by a permission gate (some Claude Code sessions
have `git-push-to-default-branch` denied), surface the local commit hash
to the user and ask them to push manually:

```
git -C ~/ev-auto-trader-canada push origin main
```

Local commits are safe — they survive across Claude Code sessions on the
same machine. They just won't reach the cloud / iOS until pushed.

## Cadence

Push at least:
- After every closed phase from `/Users/ianmcadam/.claude/plans/you-are-continuing-the-shiny-pixel.md`
- Whenever you've shipped a UI change worth seeing on the live Vercel deploy
- Before stopping a session "for now" if there are local commits

Vercel auto-deploys every push to `main` — so a push is also the deploy.

## Conflict-avoidance tips

- **Never `git rebase -i` or `git push --force` from a Claude session** without
  explicit user approval. Other sessions on other devices may have based
  work on the commits you're about to rewrite.
- **Treat `data/units.json`, `data/dealers.json`, `data/units-enrichment.json`
  as machine-generated.** If two sessions both ran the build script,
  `git pull --rebase` will conflict. Resolve by re-running the script on
  the result, not by hand-editing.
- **`data/snapshots/*.json` are append-only by date.** If two sessions
  generated a snapshot on the same date, the file is overwritten (per the
  script's idempotent-per-day design). Pick whichever is newer in `mtime`
  on conflict.

## What lives where

| File | Role | Owner |
|---|---|---|
| `NEXT.md` | Live work queue with letter-keyed items | hand-edited |
| `BLOCKERS_MEDIUM.md` | Known issues caught during medium-reasoning runs | hand-edited |
| `PROGRESS.md` | Append-only log of what shipped + when | hand-edited |
| `data/*.json` | Live data | machine-generated by `scripts/*` |
| `data/snapshots/*.json` | Daily snapshot archive | machine-generated |
| `~/.claude/plans/you-are-continuing-the-shiny-pixel.md` | Multi-phase v2 plan | edited via Claude plan-mode only |

The plan file lives in the user's home Claude config, **not in this
repo** — it's intentionally per-user, not part of the codebase. Do not
mirror it here.

## Quick-look commands

```bash
# What changed since the last sync?
git log --oneline origin/main..HEAD     # local commits ahead of cloud
git log --oneline HEAD..origin/main     # cloud commits ahead of local

# Live data health check
jq 'group_by(.msrpSource) | map({source: .[0].msrpSource, count: length})' data/units.json

# Build status (read-only, safe before commit)
npx tsc --noEmit
npx next build 2>&1 | tail -5
```
